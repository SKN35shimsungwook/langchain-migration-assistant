요약

무엇을 만들었나: 옛 버전 LangChain 코드를 넣고 바꿀 버전을 고르면, 대응표 · 공식 문서를 근거로 고치고 verifier가 LLM 없이 11가지를 검사해, 실패하면 최대 3회 다시 고치는 챗봇.

무엇을 시험했나: (A) 평가 질문 36개가 올바른 시험지인지 (B) 화면 · DB가 의도대로 동작하는지 (C) 화면이 팀 그래프를 불러 실제 결과를 보여 주는지 (D) 일반 LLM과 비교해 얼마나 나은지.

지금까지 결과: 질문 세트 검사 36/36 · 화면 · DB 자동 점검 19/19 · 최상위 그래프 세 갈래(변환 · 검색 · 일반) 연결 확인 · TiDB 저장 · 중복 검사 확인 · 그래프 연결 실행 2회 모두 3회차 통과(바뀐 6줄 모두 근거 ID) · 비교 실험 공통 기준 통과 일반 LLM 0% → 우리 챗봇 57% (실행 기준 0% → 87%, 같은 gpt-4o-mini) · 자체 평가 83.3점 (B)

1. 개요

1-1. 배경

LangChain은 1.0에서 패키지가 나뉘고 LLMChain, initialize_agent 같은 옛 체인 · 에이전트가 빠졌습니다. 인터넷의 코드는 대부분 옛 버전이라 LLM은 옛 방식을 답하고, 틀려도 모릅니다(버전 지체 환각). 연구에서도 문서가 부족하면 LLM 코드의 42.55%만, 문서를 줘도 66.36%만 목표 버전에서 실행됩니다(When LLMs Lag Behind, 2026).

1-2. 테스트 목표

목표확인 방법
시험지가 공정한가옛 코드가 1.x에서 실제로 깨지는지, 기대하는 답의 import가 1.x에서 실제로 되는지 자동 확인
화면 · DB가 의도대로 동작하는가자동 점검 봇이 로그인부터 대화 다시 열기까지 19가지를 화면으로 실행
팀 그래프와 연결되는가같은 코드를 화면 경로로 그래프에 보내 결과 모양 · 근거 ID · 검사 결과 확인
일반 LLM보다 나은가같은 질문 30개 · 같은 모델 · 같은 채점 기준으로 비교 (진행 예정)

1-3. 범위

포함: LangChain 0.0.300 ~ 0.3.30 코드를 1.x로 올리기(그래프), 질문에 적은 버전으로 바꾸기, LangChain 질문 · 일반 질문 답변, 화면, 대화 기록(TiDB). 제외: 바뀐 코드의 실제 실행 결과 비교.

'다시 시도해줘'라고 쳐도 엉뚱한 답화면이 마지막 메시지만 보내서 그래프가 이전 코드를 모름검사 실패 결과에 '같은 요청으로 다시 시도' 버튼
요청 코드에 없던 줄(ChatCerebras 등)이 생겨 3회 모두 실패검색이 상관없는 채팅 모델 연결 문서를 근거로 넘기고, 다시 쓰기가 그 예시를 베낌. 재시도 때 틀린 근거가 빠지지 않음검사기가 '기록 없는 변경(환각)'으로 정확히 잡음. 2 · 3번에 검색 필터 · 다시 쓰기 규칙 · 재시도 제외 규칙 전달
